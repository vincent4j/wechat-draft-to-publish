# 按需发布流程工作日志

## 任务概述

把 `wechat-draft-to-publish` 从“用户选择起始步骤，默认向后执行”的流程入口，改为“用户说明想得到什么，Skill 自动确定执行范围”。同时减少分步模式的无意义确认，并强化完成后的执行说明与整套发布包一致性检查。

## 完成的工作

- 将主要模式调整为“直接完成”和“边做边看”，保留旧命令兼容。
- 增加自然语言执行范围识别，支持单项、连续区间、不连续指定产物和完整发布包。
- 明确用户点名具体产物即视为该范围的执行授权，不再要求步骤编号。
- 禁止工作流自动扩大执行范围或擅自补做前后步骤。
- 边做边看改为确认正文、配图、封面和排版的实际结果，不再增加生成前方案确认。
- 摘要、朋友圈文案和机械校验不再设置单独确认门。
- 局部任务默认不清理；只有第 4—6 步均在本次范围内并验证通过，或用户明确要求时才清理。
- 增加发布包一致性检查，统一核对最终正文、封面、配图、摘要和朋友圈文案。
- 重写完整执行回执，强制说明实际完成、明确跳过、文件、校验、清理和过期风险。
- 更新 README、界面元数据和工作流契约校验。

## 问题和解决方案

### 起始步骤不能表达结束边界

旧流程只支持“从第 N 步开始”，自动模式会继续到第 6 步，与“只做封面”“只排版”这类常见请求冲突。

解决方式：先解析目标产物和排除项，再生成可包含单项、区间或指定步骤集合的执行清单。到达清单末尾立即结束，不把内部顺序当成用户授权。

### 分步模式包含双重确认

配图和封面原来可能先确认方案、生成后再确认是否继续，增加交互负担。

解决方式：工作流默认值已经足够时直接生成，边做边看只确认真实结果。首次偏好配置继续被父工作流禁止。

### 局部任务可能触发范围外清理

如果只生成朋友圈文案但目录中恰好存在其他有效产物，旧规则可能满足清理条件。

解决方式：清理除了产物有效，还要求第 4、5、6 步均属于本次范围；局部任务默认不清理。

## 本次对话复盘

这次优化延续了 `flash-writer` 的经验：用户应该选择想得到的结果，而不是学习 Skill 的内部流程。两个执行方式只是控制节奏，不形成两套质量标准；底层六项能力和检查标准保持一致。

前向测试覆盖了只做封面、从配图做到排版、模糊完整处理和真实单项摘要四种场景。前三类均正确识别范围和入口；摘要测试真实生成 73/120 字的合规文件，并在最终回执中明确列出完成项、跳过项、文件、校验和未清理原因。

## 复盘分级

**合同候选**：自然语言执行范围不得被自动扩大、局部任务默认不清理、任何执行范围结束后都必须给出完整执行回执。

## 技术决策

- 自然语言结果范围是主要入口，步骤编号只做向后兼容。
- “直接完成”连续执行清单；“边做边看”只在需要主观判断的实际结果后暂停。
- 用户明确指定单项任务即授权该单项执行；笼统请求才展示模式菜单。
- 发布包一致性检查以本次最终使用的 Markdown 正文为权威来源。
- 完整回执是结果合同，计划执行但失败的内容不能列为已完成。
